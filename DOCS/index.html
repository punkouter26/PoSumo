Tier 1 - Executive Summary

What PoSumo is, in 30 seconds

PoSumo is a physics-ragdoll sumo game where each wrestler is a 14-part 2D biped (pelvis, 4-segment torso, 2 legs x 3 segments, 2 arms x 2 segments) controlled end-to-end by a neural network policy. Four fighters are shipped (Matt, Standard, Nick, Kim) plus a deliberately brainless Bot. Brains are trained with PPO self-play via the ML-Agents Python trainer (mlagents-learn) and inferred at runtime through Unity InferenceEngine (Sentis).

Game flow

The game always boots into the tournament bracket scene (SCN_TOURNAMENT). The bracket seeds each character twice into an 8-slot single-elimination, loads SCN_SUMO for each bout, the referee scores a winner, then the bracket advances. Each match is a best-of-(tournamentPointsToWin = 2) of rounds; each round is a refereed bout on a raised dohyo.

Single round flow

Intro countdown (4 s) -> ceremonial walk-in (12 s cap) -> "HAKKEYOI!" / "FIGHT!" -> referee-driven fight (20 s cap, shrinking mat after 8 s) -> round win/loss -> 2.5 s grace -> next round.

Why this matters

The policies solve a real control problem: balance under self-applied disturbance, exploit stance geometry, push without overcommitting. The match layer is presentation, not training. Self-play ELO is the metric; mean reward is only a shaping mix.

Tier 2 - High-level Overview

Unified architecture

Four script folders, three assemblies, four shipped brains, two referees. The diagram below traces the pipeline from a YAML config through mlagents-learn to an ONNX file to inference at runtime.

What each layer does. Editor (Assets/Editor/) ships the menu tools that build envs, deploy brains, and run the harness. The training side (Training/) wraps mlagents-learn with TensorBoard and an explicit --base-port. The runtime side is four folders: Agent/, Sensor/, Reward/, Systems/. Everything that ships lives in PoSumo.Runtime; menu tools in PoSumo.Editor; tests in PoSumo.Tests.EditMode.

Dynamic lifecycle & execution loop

Each 20 ms physics tick (fixedDeltaTime = 0.02) walks a fixed sequence: collect observations, normalize, infer, slew, apply Hill+activation+fatigue, drive the joints, step PhysX 2D, sample sensors, evaluate reward, check terminals.

The Sentis runtime is what runs every .onnx file: a 3-layer dense trunk (512x3) takes a 45-float observation vector and returns 13 continuous actions. PhysX 2D integrates 14 rigid bodies per fighter at 50 Hz. Reward providers are plain C# objects that hold per-character coefficients and return floats; they cannot end an episode.

Tensor blueprint & actuator map

Observation vector (45 floats): body state (5) + 13 joint angles + 13 joint speeds + 4 foot contacts + 1 task flag (sumo or walk) + 4 opponent/target slots + 2 edge distances. Output: 13 joint drives, each mapped to a single motor.

Reward tree

Three reward trees: Sumo (upright, closing, lunge, impact, knee bend, hips low, stance, cadence), Walk (forward velocity, tall gate, bend reward, fall terminal -1, graduation +3), and Shared (energy penalty, jerk penalty, effort, step cadence). Terminals live only in Agent_Biped.

Hyperparameter matrix

Trainer: PPO, batch 2048, buffer 20480, learning rate 3.0e-4 (linear schedule), beta 5e-3, epsilon 0.2, GAE lambda 0.95, 3 epochs. Network: 3x dense 512 with input normalization. Self-play: window 25, swap/save 50k, team change 250k.

Sensor stack

  • BodyPartContact - per-foot ground contact (used by IsDown via NonFootGroundContacts).
  • Impact - impulse captured at first heavy collision in a contact pair, scaled by squared closing speed, capped at impactCap.
  • RayPerception - off by default; an opt-in sensor for edge / wall sensing.

Terminal handling

Only Agent_Biped ends an episode. The training referee (Systems_SumoMatchManager) calls AddReward(+1) on the winner and AddReward(-1) on the loser. The game referee (Systems_GameMatchManager) calls the same pair but with the round state machine wrapping it. Falling is not a loss in either referee; downOutSeconds = 3 s retires a non-getting-up fighter.

Telemetry

  • TensorBoard (port 6006) - ELO, mean reward, episode length, value loss, policy loss, entropy, per-fighter stamina.
  • HTTP :8787+ (env builds after 2026-08-07) - JSON snapshot of every fighter's position, velocity, edge distance, stamina, current round state. Raw TcpListener, 12-port walk, main-thread string assembly on a 2 Hz timer.
  • Console - [MATCH], [ROUND], HARNESS RESULT:, BUILD RESULT:, DEPLOY RESULT: are the markers MatchTestHarness and the verification flow read back.
