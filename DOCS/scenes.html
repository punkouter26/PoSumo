Build Settings

There are exactly two scenes in the project's Build Profiles. The game always boots into SCN_TOURNAMENT (build index 0), which loads SCN_SUMO (build index 1) for every bout and gets the winner back via Systems_TournamentReporter.

SCN_TOURNAMENT Build index 0

The bracket screen. Eight elastic chips per round, three rounds (Quarterfinals / Semifinals / Final), a roster palette, and a status line. Built entirely in C# at runtime via UI Toolkit - no UXML, no USS.

Manager objects in this scene

BracketSystems_TournamentBracketSeeds the 8-slot bracket, runs matches in order, advances winners, handles the drag-to-rearrange UI, optionally auto-plays. Holds the const string ARENA_SCENE = "SCN_SUMO" as the single source for which scene to load for each bout.

The bracket scene ships without an AudioListener on purpose - only the arena scene has one - and the runtime-added listener is deliberately NOT persistent: LoadScene(ARENA_SCENE) is Single mode, so it dies with the scene and never fights the arena's own listener.
UIDocumentUI Toolkit UIDocumentThe single UIDocument the bracket and the career overlay draw through. Three components used to add their own at equal sorting order, which has no defined draw or pick order; the unified document is the fix.

Bracket layout

Elastic chips (flexGrow 1, flexBasis 0, SLOT_SIZE 150 as a floor). Each round's chips sit in a Systems_UiKit.Surface card under a centred header; the roster palette is a 2-up grid of 50%-wide cells (each cell itself a Systems_UiKit.Row(), so a chip built for a row never collapses inside a default column cell).

_winnerSlots holds one entry per chip, not per match, because match 0 is both the QF-0 winner chip and the semifinal's left entrant chip. Keying by match index silently orphans the duplicate chips and they never repaint.

SCN_SUMO Build index 1

The arena. Built once, baked into the scene (an editor pass ran Systems_SumoArena.Build() and saved the children), so Awake() only rebinds references. Holds managers and two fighters; everything else (lighting, audio, presentation, damage) is new GameObject(...) at runtime by the match manager.

SCN_TRAIN_* One per fighter

Each training scene carries two populations under one behavior name: 4 sumo agents on two self-play arenas, and 6 walk agents on a lane 60 m below in Mode.Walk with no opponent. The walk lane lives in each fighter's own scene because a gait must be learned on the physique that runs it.

The "no character assigned" trap

SCN_TRAIN_STANDARD currently contains zero references to Standard_Character.asset - eight fields sit at character: {fileID: 0}. The other three training scenes reference theirs correctly. Verified by GUID-grepping the saved .unity file. It is harmless by coincidence (Standard's sheet is byte-identical to Agent_Biped's code defaults), but it becomes a real bug the moment anyone tunes the sheet.

# Verify a scene's character assignment by reading the saved .unity file
grep -n 'character:' Assets/Scenes/Training/SCN_TRAIN_STANDARD.unity

Routing - how a bracket play session flows

From boot to first match end:

  1. Boot - Unity loads SCN_TOURNAMENT (build index 0).
  2. Systems_TournamentBracket.Start() calls EnsureAudioListener() (no listener in the scene by design), seeds the bracket from _roster, draws the UI Toolkit chip grid, starts _autoTimer.
  3. Systems_TournamentState (static) initialises the 8-slot single-elimination. [RuntimeInitializeOnLoadMethod(SubsystemRegistration)] cleared it earlier so domain reload being OFF does not leak it between Play sessions.
  4. Auto-play kicks in after _autoPlay = true + _betweenMatchSeconds = 2.5 of inactivity. Bracket calls SceneManager.LoadScene(ARENA_SCENE, LoadSceneMode.Single) with the two assigned characters passed via Systems_MatchRoster.
  5. In SCN_SUMO, Systems_MatchRoster (execution order -500) assigns the two characters; Systems_GameMatchManager copies its values from GameTuning, spawns every companion, runs the round state machine.
  6. Bracket match only: Systems_TournamentReporter is spawned into the arena. On RoundEnded it observes the winner and on MatchEnded it writes back to Systems_TournamentState and loads the bracket scene.
  7. Bracket scene reloads. The bracket repaints from the new state, advances to the next match, and the loop continues until a champion is crowned.
